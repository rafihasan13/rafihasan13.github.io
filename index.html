Production blueprint (Next.js + Supabase + real money)

This Pages demo is client-side. For real withdrawable money you need a server. Deploy this way:

Stack: Next.js (TypeScript, Tailwind) on Vercel · Supabase (Postgres, Storage, Google OAuth) · Stripe (Cards/Apple/Google Pay; Bizum via Stripe EU) · Tremendous/PayPal Payouts + SEPA transfers for withdrawals · Replicate/Flux or DALL·E 3 for images (server-side, 3/match cap).

Tables (see supabase/schema.sql): profiles, wallets (credits_cents, cash_cents), ledger (double-entry: debit/credit, escrow→settled), rooms (size, entry_cents, theme sealed), entries, submissions, votes (voter, a, b, winner, weight), payouts, revenue.

Server authority required: OAuth session (Supabase Auth Google), escrow locking in a Postgres transaction, server-side countdown (rooms.starts_at/ends_at), generation proxy that enforces 3/match, vote API that excludes self + enforces 10-vote qualification + deposit-weighted Bayesian weight, settlement job computing Bradley-Terry/Elo then crediting cash + logging 20% rake. Never trust client timers or balances.

Env: NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, STRIPE_SECRET_KEY, REPLICATE_API_TOKEN / OPENAI_API_KEY, TREMENDOUS_API_KEY, PAYPAL_CLIENT_ID/SECRET.
